# extension-problems-cli

<a href="https://www.aihonestybadge.com" target="_blank" rel="noopener"><img src="https://www.aihonestybadge.com/badges/ai-generated-small.svg" alt="AI Generated" height="20"></a>

This is an AI-generated (and substantially AI-documented) tool designed to help connect AI tools (or other automated tooling) to problem reports generated by extensions for Visual Studio Code and other compatible editors.

**This project is not affiliated with Microsoft, the makers of Visual Studio Code!**

It is also not affiliated with SonarSource Sàrl's [SonarQube](https://www.sonarsource.com/products/sonarqube/), the origin of the "SonarQube for IDE" extension used in the examples. They have a fancy cloud-based code quality analysis tool with a *real* CLI, and even an MCP server integration, which is almost certainly what you want to be using instead of trying to run their IDE extension without a full human-operated IDE.

## Setup

You need Node.js 20.12 or newer. Run the tool straight from GitHub with
`npx github:adamnovak/extension-problems-cli`.

You also need the extension you want to run, as a `.vsix` file.

## Running

Give it the extension and the files or directories to analyze. It searches
directories recursively, skipping hidden ones and `node_modules`:

```
npx github:adamnovak/extension-problems-cli --extension EXTENSION.vsix src test
```

For C or C++, give it your compilation database instead. It analyzes every
file listed there:

```
npx github:adamnovak/extension-problems-cli --extension EXTENSION.vsix \
    --compile-commands build/compile_commands.json
```

`--setting KEY=VALUE` sets an extension setting, as in VS Code's
`settings.json`. If the results look wrong, add `--log FILE` and read what
the extension logged.

## Output

The tool prints a JSON object. Its `problems` list has one entry per
problem, with `file`, `line`, `column`, `endLine`, `endColumn`, `severity`,
`message`, `source`, and `code`. Lines and columns start at 1.

With `--format pretty` it prints one line per problem instead:

```
FILE:LINE:COLUMN: SEVERITY: MESSAGE [SOURCE CODE]
```

The exit status is 0 when the extension reported on every file. It is 2 when
some files got no report within `--timeout` seconds (30 minutes by default);
those files are listed in `unanalyzedFiles`. It is 1 when the tool failed.

## Example: Running SonarQube for IDE

In this example, we will run the LGPL 3.0 [SonarQube for IDE](https://github.com/SonarSource/sonarlint-vscode) (formerly SonarLint) extension. The SonarQube authors license a number of their powerful proprietary static analysis tools [to users of their extension, and *only* for use with their extension](https://github.com/SonarSource/sonarlint-vscode/blob/e5d65b4e0e5ebdef4dcdff6d83fb090e69cfb38f/NOTICE.txt).

The extension needs Java 21 or newer, so make sure that is installed. On Ubuntu:

```
sudo apt install openjdk-21-jre-headless
```

Download the extension from its
[releases](https://github.com/SonarSource/sonarlint-vscode/releases), taking
the file without a platform in its name:

```
curl -LO https://github.com/SonarSource/sonarlint-vscode/releases/download/6.1.0%2B91156/sonarlint-vscode-6.1.0.vsix
```

Analyze a C++ project:

```
cd ~/project
npx github:adamnovak/extension-problems-cli --extension ~/sonarlint-vscode-6.1.0.vsix \
    --compile-commands build/compile_commands.json
```

The first run takes longer while the extension downloads its C/C++ analyzer.
The tool waits for the download, so the results are still complete.

```json
{
  "extension": "SonarSource.sonarlint-vscode",
  "problems": [
    {
      "file": "/home/you/project/src/util.cpp",
      "line": 11,
      "column": 12,
      "endLine": 11,
      "endColumn": 17,
      "severity": "warning",
      "message": "Division by zero [+4 locations]",
      "source": "sonarqube",
      "code": "cpp:S3518",
      "collection": "sonarlint"
    }
  ],
  "unanalyzedFiles": []
}
```

Analyze a JavaScript project's source and tests:

```
npx github:adamnovak/extension-problems-cli --extension ~/sonarlint-vscode-6.1.0.vsix src test
```

Turn off a rule by its code:

```
npx github:adamnovak/extension-problems-cli --extension ~/sonarlint-vscode-6.1.0.vsix \
    --setting 'sonarlint.rules={"cpp:S5827":{"level":"off"}}' \
    --compile-commands build/compile_commands.json
```

## Running from source

To change the tool, or to add an extension configuration, clone it and
install its dependencies:

```
git clone https://github.com/adamnovak/extension-problems-cli.git ~/extension-problems-cli
cd ~/extension-problems-cli
npm install
```

Then run your copy from any directory with `npx ~/extension-problems-cli`
in place of `npx github:adamnovak/extension-problems-cli`.

## Adding More Extensions

Some other extensions might Just Work.

If they don't, you might need to add a configuration file in `extension-configs/` for the name of the extension. This should include default extension settings under `settings`.

It is recommended to disable any form of extension telemetry that can be configured to be off, because telemetry sent from an extension running in a very unusual environment like this one is not likely to be useful to extension authors.

If the extension isn't ready to analyze files immediately on startup (for example, because it downloads more components at runtime), and it is based around a language server that exposes whether it is ready, you can also write a `readiness` section to get this tool to wait for the extension to be ready. (This aspect of the tool almost certainly needs work to support more kinds of extensions and ways of exposing readiness.)
